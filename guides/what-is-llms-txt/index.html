What is llms.txt, and does your business need one?

llms.txt is a plain-text file at the root of a website that tells language models what the site is, in the site's own words. It sits beside robots.txt and the sitemap, in the layer of a site that exists to instruct machines. Where robots.txt tells crawlers where they may go and the sitemap lists every URL, llms.txt does a different job: it states the business's name, what it sells, where it works, and which pages matter, in clean markdown that a language model can read in one pass. Gerris publishes one for this site, linked in the footer of every page, and builds one into every site it delivers. This guide explains what the file is, what goes in it, and what it honestly can and cannot do.

Where did llms.txt come from?

The format was proposed in 2024 by Jeremy Howard as a standard location and structure for information meant for large language models. The problem it answers is real: a modern web page arrives at a model wrapped in navigation, scripts, and layout markup, and the model spends its limited attention digging the facts out of the furniture. A plain markdown file removes the digging. The proposal is a convention, not a law of the web. No engine is required to read the file, and adoption is voluntary on both sides, which is exactly the state robots.txt was in when it became universal.

What goes in an llms.txt file?

The structure is short and fixed. The file opens with the business's name as a heading. Under it, a summary in blockquote form: one short paragraph stating what the business is, what it sells, where it works, and how to reach it, written the way the business would state it on the record. Then come sections of links, the pages that matter, each with a one-line description of what the page says. A key facts section closes the file: prices, service areas, credentials, founding facts, the statements the business most needs repeated correctly. This site's llms.txt carries its prices and its audit scope as key facts, because those are the statements buyers ask engines about and the ones engines most often get wrong from scattered pages.

The discipline is selection. The file is a summary, not a copy of the site. A business that pastes forty pages into it has built a second website in a worse format. Ten to twenty links, the facts that decide purchases, nothing else.

What is llms-full.txt?

The companion convention. Where llms.txt links to the pages that matter, llms-full.txt contains the full text of those pages in one markdown document, so a model or an agent can take in the whole record in a single fetch without crawling page by page. Gerris publishes both. The summary file serves a quick lookup; the full file serves a deep one, an agent researching a vendor, a model assembling a record it intends to rely on. Keeping the two in step is maintenance, the same kind a sitemap needs, and it belongs to whoever maintains the site.

Do AI engines actually read llms.txt?

Server logs settle part of this: AI crawlers and agents fetch the file, on this site and on client sites, and fetch it early in a visit, before the deep pages. What no engine has promised is a ranking or a citation in exchange for having one. The honest claim is narrower and stronger. The summary of your business gets written whether you take part or not, assembled from whatever the engines find. llms.txt is the one place where that summary is stated by you, in full sentences, in a form built for the reader who will repeat it. A business that declines to state its own record is leaving the stating to directories, reviews, and competitors' comparisons.

How do you keep an llms.txt file true?

The same way you keep a sitemap true: by tying it to the site's one set of facts and updating it in the same pass as the pages. When a price changes, the price changes on the services page, in the schema, and in the key facts section of llms.txt, in one edit, from one source. When a page is retired, its link leaves the file. The failure mode to avoid is the orphaned file, written once at launch and never touched again, still stating the old phone number and the old service area two years later in the business's own voice. An engine that finds the file and the site disagreeing believes the disagreement is real and reports both versions, which is worse than the file never existing. Gerris treats the machine layer, robots.txt, sitemap, schema, llms.txt, as one document in four formats, and maintains it that way.

How is llms.txt different from robots.txt and a sitemap?

Each file in the machine layer answers a different question. Robots.txt answers where crawlers may go, and the crawler guide covers the decisions it carries. The sitemap answers what URLs exist. Schema answers what the facts on a page mean, in structured form, and the schema guide covers that layer. llms.txt answers the question none of the others ask: what is this business, stated plainly, by itself. The four files agree or the record blurs, which is why Gerris writes them as one layer, from one set of facts.

Frequently asked questions

Does having an llms.txt file improve my rankings?

No engine has promised that, and any vendor who guarantees it is inventing the promise. What the file does is verifiable from your own server logs: AI crawlers fetch it, and they fetch the summary you wrote instead of assembling one from scattered pages. It is a statement of record, cheap to publish and cheap to keep correct, not a ranking lever.

Where does the llms.txt file live?

At the root of the domain, at yourdomain.com/llms.txt, in plain text with markdown formatting. One file per site. The companion full-text version lives beside it at /llms-full.txt. Both are linked from this site's footer if you want to read a working example before writing yours.

What should a small business put in its llms.txt?

The name of the business, a one-paragraph statement of what it sells and where, links to the homepage, the services pages, and the about page with one-line descriptions, and a key facts section: service area, prices where they are published, credentials, phone, and email. If a fact decides whether a buyer calls, it belongs in the file.

Who writes and maintains llms.txt?

Whoever maintains the website, working from the same facts the site states. Gerris writes the file as part of every site build and updates it when prices, services, or facts change, because a stale llms.txt is worse than none: it states the old record in the business's own voice, and the engines will believe it.
