What is IndexNow, and does it help AI search?

IndexNow is an open protocol a website uses to tell search engines the moment a URL is added, updated, or deleted. The IndexNow site lists Microsoft Bing, Naver, Seznam.cz, Yandex, and Yep as supporters, and a URL submitted to one participating engine is shared automatically with all the others. For AI search, the reason to use it is Bing. Microsoft says IndexNow helps keep information fresh across search and AI experiences, and the Bing index feeds Microsoft Copilot and the AI summaries in Bing.

Why does freshness matter for AI answers?

Because an AI answer repeats the version of a page its index holds. A business that corrects its hours, adds a service, or fixes a wrong fact on its website changes nothing in the answer until the engine has recrawled the page and rebuilt its record. Until then, the answer quotes the old page, and the buyer acts on it.

Microsoft states the connection directly. In its February 2026 announcement of the AI Performance report, it says that by enabling faster discovery of content changes, IndexNow helps ensure that AI systems reference the current versions of pages. The guide to fixing wrong information in AI answers describes the wait between the fix and the changed answer. IndexNow shortens the part of that wait that belongs to Bing and its partners.

How does IndexNow work?

In three parts: a key that proves you own the site, a key file that publishes it, and a notification that names the changed URLs.

  • The key: between 8 and 128 characters, using lowercase and uppercase letters, numbers, and dashes.
  • The key file: a UTF-8 text file named for the key and holding the key, at the root of the site. The documentation also allows key files elsewhere on the same host, as long as each notification says where with a keyLocation value.
  • A single URL: a request to an engine's endpoint that names the changed URL and the key.
  • Many URLs: a JSON POST listing the changed URLs, up to 10,000 per post.

A single submission and a bulk submission look like this, with example values:

GET https://api.indexnow.org/indexnow?url=https://www.example.com/services/&key=3f8a2c9d41e0b7a6

POST /indexnow HTTP/1.1
Host: api.indexnow.org
Content-Type: application/json; charset=utf-8

{
  "host": "www.example.com",
  "key": "3f8a2c9d41e0b7a6",
  "keyLocation": "https://www.example.com/3f8a2c9d41e0b7a6.txt",
  "urlList": [
    "https://www.example.com/services/",
    "https://www.example.com/hours/"
  ]
}

The response code says what happened. The documentation defines 200 as submitted successfully, 202 as received with key validation pending, 400 as an invalid format, 403 as a key that is missing or does not match the key file, 422 as URLs that do not belong to the host or a key that does not match the protocol's format, and 429 as too many requests, flagged as potential spam.

When should a site send a notification?

Every time a page is added, updated, or deleted, automatically. The documentation recommends automating submission as soon as content changes. On a site built by hand, that means a step at the end of every publish that sends the changed URLs. On a content management system or a CDN that offers IndexNow as a built-in setting or plugin, it means turning that setting on and checking that it fires.

Send the pages that changed, and only those. A notification for an unchanged page spends the engine's attention on nothing, and resubmitting a whole site on every publish is the pattern the 429 response exists to stop. Deleted pages count too: a notification for a removed URL tells the engine to drop it, which keeps a retired service or a closed location out of the answer.

How do you set up IndexNow on a site you publish yourself?

Five steps, done once, then run on every publish:

  • Make a key: 32 hexadecimal characters is a comfortable length inside the 8 to 128 the protocol allows. On a Mac or Linux machine, openssl rand -hex 16 prints one.
  • Publish the key file: save the key as the only line of a text file named for the key, such as 3f8a2c9d41e0b7a6.txt, at the root of the site, and confirm it loads in a browser.
  • Collect the changed URLs: on a site kept in git, the files changed by the last commit map to the pages that changed; on a content management system, the publish log does the same.
  • Send them: one POST to an IndexNow endpoint with the host, the key, the key location, and the list.
  • Read the response: a 200 or 202 is the receipt; a 403 means the key file is missing or wrong, and a 422 means a URL in the list belongs to another host.

For a static site in git, the whole step fits in a few lines of shell run after each deploy, with example values:

KEY=3f8a2c9d41e0b7a6
HOST=www.example.com
URLS=$(git diff --name-only HEAD~1 HEAD -- '*.html' \
  | sed -e 's#index\.html$##' -e "s#^#https://$HOST/#" \
  | jq -R . | jq -s -c .)
curl -s -o /dev/null -w '%{http_code}\n' \
  -H 'Content-Type: application/json; charset=utf-8' \
  -d "{\"host\":\"$HOST\",\"key\":\"$KEY\",\"keyLocation\":\"https://$HOST/$KEY.txt\",\"urlList\":$URLS}" \
  https://api.indexnow.org/indexnow

The script prints the response code, which goes into the publish log beside the commit. That log, read against Bing Webmaster Tools, is the record of which fixes reached the engine and when.

Does Google use IndexNow?

Google is absent from the list of participating engines on the IndexNow site. Google learns about changed pages through its own crawling, sitemaps with accurate lastmod dates, and the URL Inspection tool in Search Console, which can request that a single page be recrawled. Since Google AI Overviews and AI Mode draw on the Google Search index, a fact corrected on the website reaches them on Google's crawl schedule. The indexing guide covers the Google side.

The practical answer is to run both. A sitemap and Search Console for Google, IndexNow for Bing and the engines that share its notifications, and one source of truth on the website for all of them.

What does IndexNow leave out?

IndexNow is a notice. It tells an engine which URLs changed so the engine can prioritize crawling them. Indexing, ranking, and citation are still the engine's decisions, made on the content of the page, and the IndexNow site promises none of them. A notification for a thin page brings the engine back to a thin page sooner.

Bing Webmaster Tools shows what happened next. Microsoft says its IndexNow Insights report gives site owners actionable insights on the URLs they submitted, including indexing status and crawl errors. Read it beside the AI Performance report, which counts how often Copilot and Bing AI answers cite those pages once they are indexed.

Frequently asked questions

Is IndexNow free?

Yes. IndexNow is an open protocol with no fee and no account required to submit. A site needs only a key and a key file at its root. Bing Webmaster Tools, which is free, reports on the URLs a verified site has submitted.

Does IndexNow replace a sitemap?

No. Keep the sitemap, with accurate lastmod dates, because Google reads it and Google is absent from IndexNow's participating engines. IndexNow adds an immediate notice for Bing and the engines that share its submissions.

If I submit to Bing, do the other engines get it?

Yes. The IndexNow documentation says submitted URLs are automatically shared with all other participating search engines, so one submission to any of them reaches the rest.

What does a 202 response mean?

The URL was received and the key has not been validated yet. The engine checks the key against the key file on your site, and a 403 follows if the key file is missing or holds a different key.
